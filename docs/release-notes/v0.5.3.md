Lyrion Anywhere **0.5.3** makes the gateway's database reads independent of its writes, so a busy or slow disk no longer makes every request wait, and finishes the version display in the web app. It goes with Android [1.15.4](https://github.com/JameZUK/lyrion-anywhere/releases/tag/android-v1.15.4). Update from *Settings › Plugins* in LMS; LMS restarts to load it.

**Install or update:** add this repository in *Settings › Plugins › Additional repositories* (if you haven't already), then install or update **Lyrion Anywhere**:

```
https://github.com/JameZUK/lyrion-anywhere/releases/latest/download/repo.xml
```

## Gateway

- **Reads no longer wait for writes** (review item M7, completed). The gateway keeps its accounts, devices, tokens, ratings and history in one SQLite file. Since 0.5.0 the writes ran off the request workers, but every request still began with a read (which players the user may see) through the same connection and lock as the writes, so a write stalled on the disk made every request queue behind it. The gateway now opens a second, read-only connection for the request path. SQLite's write-ahead log lets readers run alongside the writer and see every committed write, so a stalled write holds up nothing but itself. The loopback admin commands' writes run off the async workers as well. Tests prove a request completes while a write is stuck, that the read connection sees a write the moment it commits, and that a write through the read connection is refused.

## Web app

- **Settings › About shows the plugin's version.** It had shown the web app's own package version, which never changed, so every release read "0.1.0". The build now takes the version from the plugin's `install.xml`, the release the web app ships in.

Everything from [0.5.2](https://github.com/JameZUK/lyrion-anywhere/releases/tag/v0.5.2) (the first GitHub issue fixes, the authentication hardening and the schema-13 migration) is included.
