Lyrion Anywhere **0.7.5** makes transcoding work on piCorePlayer and tells you what ffmpeg the gateway found. The player protocol stays at 2, so **Lyrion Anywhere for Android 1.17.0** or later keeps working, and there is no Android release this time.

**Install or update:** add this repository in *Settings › Plugins › Additional repositories* (if you haven't already), then install or update **Lyrion Anywhere**:

```
https://github.com/JameZUK/lyrion-anywhere/releases/latest/download/repo.xml
```

## Transcoding

- **ffmpeg's own Opus encoder is used when libopus is missing.** piCorePlayer's `pcp-ffmpeg.tcz` has no libopus and no MP3 encoder, only ffmpeg's built-in Opus encoder, and the gateway used to look for libopus alone. Now it accepts the built-in one too (libopus is still preferred where both exist), so on piCorePlayer the lower-data streams (*High* and *Data saver*) and Opus downloads work with the ffmpeg it ships. MP3 downloads still need an ffmpeg with libmp3lame, because ffmpeg has no MP3 encoder of its own; a static ffmpeg build kept on persistent storage, with its path in *ffmpeg path*, gives you that. Reported in [#29](https://github.com/JameZUK/lyrion-anywhere/issues/29).
- **The settings page says what the gateway found.** A line under the Status rows reads, for example, *Transcoding with /usr/bin/ffmpeg: MP3 (libmp3lame), Opus (libopus); lower-data streams for mobile data on*, or says why there is none: turned off, no ffmpeg on the system path, not an executable file, could not be run, or neither encoder. Before, only the gateway's log said.
- The install guide names the encoders, covers piCorePlayer, and has a troubleshooting row for "downloads offer only the original".

The full list is in the [changelog](https://github.com/JameZUK/lyrion-anywhere/blob/main/CHANGELOG.md).
