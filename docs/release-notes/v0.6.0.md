Lyrion Anywhere **0.6.0** adds a built-in Cloudflare Tunnel: with a domain on Cloudflare, the plugin alone now makes your server reachable from the internet, with no reverse proxy, no certificate and no forwarded port. Update from *Settings › Plugins* in LMS; LMS restarts to load it.

**Install or update:** add this repository in *Settings › Plugins › Additional repositories* (if you haven't already), then install or update **Lyrion Anywhere**:

```
https://github.com/JameZUK/lyrion-anywhere/releases/latest/download/repo.xml
```

## Built-in Cloudflare Tunnel

A new **Cloudflare Tunnel** section on the plugin's settings page. The gateway runs Cloudflare's `cloudflared` on the LMS machine; it dials out to Cloudflare, and Cloudflare serves `https://music.example.com` from its network. Nothing is downloaded or run until you press **Install**. The walkthrough is [INSTALL.md, Option C](https://github.com/JameZUK/lyrion-anywhere/blob/main/docs/INSTALL.md#option-c-built-in-cloudflare-tunnel).

- **Two ways to register.** *I have a tunnel token*: create the tunnel in Cloudflare's dashboard, point its public hostname at the gateway (`http://127.0.0.1:9443`), and paste the token with the hostname. *Create it for me*: paste a Cloudflare API token with *Account › Cloudflare Tunnel › Edit*, *Zone › DNS › Edit* and *Zone › Zone › Read*, and the hostname you want; the gateway creates the tunnel, points it at itself, adds the DNS record and fetches the tunnel token. An existing DNS record is left alone unless you tick *Replace an existing DNS record*, and a failed step names itself and deletes the half-made tunnel.
- **Try a temporary tunnel** with no account at all: a random `trycloudflare.com` address, shown as a link and a QR code, that stops after one hour. It is for testing only, and anyone who has the address can reach the sign-in page while it runs.
- **What is kept, and what isn't.** The tunnel token is the only secret stored (mode 0600 in the gateway's data folder). The API token is used for that one exchange and never stored or logged, and nothing about the temporary tunnel is stored.
- **Pinned and checked.** `cloudflared` 2026.10.1 is fetched only from Cloudflare's GitHub releases and only if it matches the SHA-256 built into this release. It never updates itself; a later release that moves the pin offers **Update**. It runs without a shell, with fixed arguments and an environment of only the token, `HOME` and `PATH`, and its log on the page is scrubbed of tokens and ids.
- **Settings follow the tunnel.** While it runs, the gateway accepts the tunnel's address and reads each visitor's address from `CF-Connecting-IP`, so *Public URL* and *Client address header* need no change; *Add a device* QR codes use the tunnel's address. **Stop**, **Start**, **Update** and **Remove** are on the page, and a registered tunnel starts again with LMS.
- **Needs** Linux on x86_64, aarch64 or armhf (the plugin's own platforms), and outbound access to `github.com` (port 443) and Cloudflare's network (port 7844, UDP and TCP). Docker users run a `cloudflared` sidecar instead ([DEPLOY.md](https://github.com/JameZUK/lyrion-anywhere/blob/main/docs/DEPLOY.md#cloudflare-tunnel-with-docker-a-sidecar)).
- Cloudflare Tunnel is Cloudflare's service, under [Cloudflare's terms](https://www.cloudflare.com/terms/); this plugin only sets it up for you.

## Gateway

- New options `--cloudflared <path>` (run a system-installed `cloudflared` instead of the pinned download) and `--no-tunnel` (turn the built-in tunnel off).
- The gateway now also stops cleanly on SIGTERM, stopping `cloudflared` with it.

The full list is in the [changelog](https://github.com/JameZUK/lyrion-anywhere/blob/main/CHANGELOG.md).
