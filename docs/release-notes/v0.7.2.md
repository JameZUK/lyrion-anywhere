Lyrion Anywhere **0.7.2** gives the **web app** its Back and Forward buttons back, and makes a route typed into the address bar open properly again. Both had been broken since 0.6.4 (23 October), including in 0.7.0 and 0.7.1. The gateway and the plugin are otherwise as in [0.7.1](https://github.com/JameZUK/lyrion-anywhere/releases/tag/v0.7.1); Android [1.16.0](https://github.com/JameZUK/lyrion-anywhere/releases/tag/android-v1.16.0) is unchanged. Update from *Settings › Plugins* in LMS; LMS restarts to load it.

**Install or update:** add this repository in *Settings › Plugins › Additional repositories* (if you haven't already), then install or update **Lyrion Anywhere**:

```
https://github.com/JameZUK/lyrion-anywhere/releases/latest/download/repo.xml
```

## What was wrong, and the fix

The web app handles a change of address made outside its own router (an edited address bar, a link from another page or app) itself, so that the page is not reloaded and playback is not interrupted: it steps back over the entry the browser made and then follows the route like a link. It told the router's own history entries apart from the browser's by the name of a key the router stores with each entry. The SvelteKit 3 upgrade in 0.6.4 moved that bookkeeping to another key, so the app took **every Back and Forward for an outside change** and stepped back over it: Back from Search after Settings landed two pages back with the Now playing page still showing, Forward did nothing visible, and a route typed into the address bar was lost, with a reload on the next Back.

- **Fixed:** the app recognises a router entry by the prefix shared by every key the router has ever used, not by one key's name, so Back and Forward are left to the router again and a typed route opens in the app without a reload.
- **Routes typed faster than they are routed** (several stray entries in a row) are stepped over one by one, three at most; before, a second one left the app stuck on it.
- The installed (home-screen) app updates itself to this version, as 0.7.1 introduced; a device that is playing gets the quiet *A new version is ready* offer instead, and the update applies when playback there stops.

## Also in this release

- The CI release job's timeout is 45 minutes (it takes 20 to 28), so a stalled runner fails an hour sooner.
- A mobile player test waits for the stop to be acknowledged before cutting the link, so it no longer fails on a heavily loaded machine.

## Tests

The history tests now carry the SvelteKit 3 shape of a router entry alongside the SvelteKit 2 one; a unit test reads the installed SvelteKit's own constants and checks that every history key it exports is recognised, so a future rename fails a test rather than Back; the bounded stepping is tested. An opt-in browser check (`web/app/tests/e2e/history.mjs`, Playwright against the demo library) drives Back, Forward, a typed route and two routes typed at once in a real browser: twelve of its checks fail on the 0.7.1 build and all pass on this one.

The full list is in the [changelog](https://github.com/JameZUK/lyrion-anywhere/blob/main/CHANGELOG.md).
