Lyrion Anywhere **0.5.0** is a security and robustness release for the server side, from a full review of the whole project, and goes with Android [1.15.2](https://github.com/JameZUK/lyrion-anywhere/releases/tag/android-v1.15.2). Update from *Settings › Plugins* in LMS; LMS restarts to load it.

**Install or update:** add this repository in *Settings › Plugins › Additional repositories* (if you haven't already), then install or update **Lyrion Anywhere**:

```
https://github.com/JameZUK/lyrion-anywhere/releases/latest/download/repo.xml
```

## Highlights

**Security**
- **The plugin's settings can only be changed on its settings page.** The gateway's listen address, public URL, trusted proxies, client-address header, ffmpeg path, download cache size and gateway path could be set with LMS's own `pref` command, which any page a LAN user opens can call. Values changed that way are now put back at the next gateway start, and the settings page says so.
- **Web addresses typed into searches or menus are checked before they reach LMS:** a name that resolves to a private or loopback address is refused, and typed addresses may only use ports 80 and 443.
- **Your devices** (new in this release, with Android 1.15.2): a signed-in user can see every device signed in to their account and sign out the ones they don't want. Each device has its own request allowance, so a lost or stolen device cannot block its owner from signing it out, and the audit log names the device that acted.
- **Bounded work for LMS:** track-start lookups are coalesced and capped per session, and a ratings batch runs one at a time per user with a time limit, so a client cannot turn its requests into unbounded work on the music server.

**Sync groups with a phone or a web player**
- **No more dropouts every two seconds.** A web player in media-element mode (Safari, and any browser playing in the background) applied LMS's small sync corrections by seeking the element, which stalled it; LMS then repeated the correction for ever. Corrections are now made in the audio itself and registered at once.
- **A phone that loses its connection no longer upsets the group.** The gateway's stand-in reports for a player that is briefly away now keep pace with the clock instead of freezing at the end of the track, stale heartbeats the phone queued while away are dropped rather than replayed, and sync corrections LMS sent while it was away are not delivered late. Before, a reconnect could make LMS re-base the phone's clock hundreds of times and skip it several seconds ahead.

**Reliability**
- **A slow disk no longer stalls every player:** the gateway's database writes run off the request workers.
- **The web player survives a malformed Opus packet** that could stop it, and the Opus decoder's leftover upstream debug code, which tried to open a log file on every frame, is removed.
- **The player core no longer gets stuck** when LMS replaces a track that is still decoding, or refuses a codec.

**Web app**
- Removing downloads asks first and runs once.
- Sign-in says whether a proxy dropped the request, the music server is busy or the server had a problem, instead of "check your connection" for everything.
- *Your devices* retries a failed load and keeps the list right after a sign-out.
- A proxy's fallback page is no longer taken for a successful answer, and artwork is no longer forced from a browser cache shared between accounts.

**Plugin and releases**
- The plugin reports its real version.
- The repository URL above is guarded: Android releases stay pre-releases on GitHub, and a check after every release makes sure the URL still serves the plugin.

The full list is in the [changelog](https://github.com/JameZUK/lyrion-anywhere/blob/main/CHANGELOG.md).
