Lyrion Anywhere **0.5.2** fixes the first bugs reported on GitHub after the forum announcement, and hardens the gateway's sign-in and session handling from the remaining low findings of the October code review. Android [1.15.3](https://github.com/JameZUK/lyrion-anywhere/releases/tag/android-v1.15.3) remains current. Update from *Settings › Plugins* in LMS; LMS restarts to load it.

**Install or update:** add this repository in *Settings › Plugins › Additional repositories* (if you haven't already), then install or update **Lyrion Anywhere**:

```
https://github.com/JameZUK/lyrion-anywhere/releases/latest/download/repo.xml
```

The gateway's accounts database is upgraded automatically on the first start (schema 13): every user, device and sign-in is kept, and nobody has to sign in again.

## Fixes from GitHub issues

- **Ratings on phones showed blank** ([#14](https://github.com/JameZUK/lyrion-anywhere/issues/14)). The one star beside the title on Now playing lit only for a rating made in Lyrion Anywhere itself, so a track rated 4 or 5 stars in LMS showed blank on an iPhone while the wide layout's five stars showed it. It now lights for the rating shown: yours in the accent colour, or LMS's rating muted, with the label "Rated 4 of 5 on the server". A tap still loves the track or clears your own rating. The heart style behaves the same.
- **Downloads played over the stream** ([#11](https://github.com/JameZUK/lyrion-anywhere/issues/11)). Playing a downloaded album while this device streamed from LMS left both audible, with the transport on the downloads and no way to reach the stream. Starting downloads now pauses whatever this device plays for the server first (through LMS when in reach, held on the device when out of reach), and the server's music starting on this device stops the downloads.
- **Documentation** ([#13](https://github.com/JameZUK/lyrion-anywhere/issues/13)): read-ahead, the replay cache and downloads standing in for streams are the Android app's; a browser holds only the current track. A browser cache-ahead is noted as a later improvement.

## Gateway: sign-in and sessions

Seven low findings from the 15 October review, each with a regression test that failed before its fix:

- A successful sign-in no longer clears the whole address's failure record, so an attacker with an account of their own cannot reset the cross-username lock.
- A correct password without its two-step code is now counted against the address and audited (`login.totp_required`), instead of being an unlimited way to have passwords checked.
- The account-change lock (password change, two-step set-up and removal, pairing codes) is per user **and device**, so one stolen 15-minute token cannot lock the owner out on every device.
- Device ids are never reused: the devices table is rebuilt with `AUTOINCREMENT`, and a revoked or deleted device's learned menu allow-list is forgotten rather than inherited by the next device.
- A player socket whose channel had already closed is now held for resume like a dropped socket, instead of LMS dropping the player after about 15 seconds.
- Signing in again on a device keeps at most its newest four unused refresh tokens, so the table no longer grows without bound.
- Signing out records which device did it, and revoking an already-revoked device changes nothing on the admin path too.

## Also

- Oversized LMS event lines that the gateway never forwards (menu and display notifications) are no longer logged as warnings.
- The web app names the stream actually heard (quality badge and signal path) and explains *Automatic* streaming quality per browser, from 0.5.1.
- Protocol and specification documents updated for the new rate limits and audit events.
