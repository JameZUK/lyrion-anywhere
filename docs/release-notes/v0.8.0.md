Lyrion Anywhere **0.8.0** is a security and reliability release: the fixes from a full review of the project. The player protocol stays at 2, so **Lyrion Anywhere for Android 1.17.0** or later keeps working; **Android 1.18.0** goes out alongside with the app's share of the fixes, and updating both is recommended.

**Install or update:** add this repository in *Settings › Plugins › Additional repositories* (if you haven't already), then install or update **Lyrion Anywhere**:

```
https://github.com/JameZUK/lyrion-anywhere/releases/latest/download/repo.xml
```

## What you may notice after updating

- **The settings page answers only at the server's own address:** its IP address, `localhost`, the server's host name, or a name you list under *Advanced › Other names for this page*. Opened under any other name (through a reverse proxy, say) it shows how to proceed: open it once by IP address and add the name. This closes a way for a web page to read the settings page through DNS rebinding.
- **Enabled, the admin port, transcoding and track analysis** can be changed only on the settings page. Changed with LMS's `pref` command they are put back and the status says so, so a web page someone on your network opens can no longer turn remote access back on. The admin port has a field of its own under *Advanced*.
- **A setting the page refuses keeps its saved value.** A typo in *Trusted proxies*, for example, used to clear the working value while saying it was not saved.
- **HSTS comes from the gateway.** If your reverse proxy adds `Strict-Transport-Security` too, you can remove it there (the examples no longer have it); leaving it does no harm.
- **Web app:** signing out in one tab signs out the others; a proxy's or firewall's error page no longer signs you out; the *Resume* and *Radio* shortcuts and "Search on…" links ask for a tap when opened from outside the app.

## Security

- **Crafted input can no longer tie up the server or the player:** text in LMS's answers and a stream's WAV markers were checked in quadratic time; a stream declaring a sample rate of 0 or an absurd one hung the track or filled memory; the web app's files were read and hashed on every request, signed in or not.
- **Lockouts:** a stranger could keep a user locked out by using up the shared allowance of sign-in attempts. A user's own devices and password changes now have an allowance of their own.
- **Password resets:** an admin reset, or disabling a user, now also cancels unused pairing codes and any sign-in still being checked against the old password.
- **Audit log:** refused pairing-code requests can no longer flood it.
- **Revocation at once:** revoking a device or a player permission closes or narrows that device's live connection immediately, not within 30 seconds.
- **Also:** per-user limits on `/v1/rpc` and on live re-encoding; small request-body limits per path; plain HTTP from the server's own machine only for `localhost` or an IP address; `cloudflared` is checked against its pinned checksum before every start; `anywhere restart` no longer shows the page's token to LMS CLI listeners; the bundled SQLite and `rustix` are past two advisories published this week (RUSTSEC-2026-0459, RUSTSEC-2026-0486).

## Reliability

- A sign-in that simply **expired is reported as expired**, so Android 1.18.0 keeps its downloads (only a revoked device loses them).
- A mistyped password on two-step set-up, two-step off and "Add another device" is sent once and answered 403 (it was sent twice, counting double towards a lockout).
- "Play on this device" in the web app reports a failed start instead of staying on "Starting…", retries a failed change of sample rate, backs off when a server greets and drops it, and gives up on a request after 15 seconds.
- Live re-encode slots are freed when a stream is abandoned or never fetched; database and file work no longer runs where it could hold up players' heartbeats.
- A stream of undecodable packets fails instead of "finishing" silently; a sync skip past a short track starts it.
- An ARMv6 server (Raspberry Pi 1, the first Pi Zero) gets a plain message that its processor is too old, instead of a gateway that crashes.

The database moves to schema 16 on first start; there is nothing to do. The `cloudflared` version is unchanged from 0.7.7.
