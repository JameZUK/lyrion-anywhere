Lyrion Anywhere **0.7.3** changes the player protocol: **update both** the plugin and the Android app together. The plugin's player needs **Lyrion Anywhere for Android 1.17.0** or later (an older app is told to update when it tries to play on the phone; it can still control other players), and app 1.17.0 needs this plugin or later to play on the phone. The web app ships inside the plugin and always matches.

**Install or update:** add this repository in *Settings › Plugins › Additional repositories* (if you haven't already), then install or update **Lyrion Anywhere**:

```
https://github.com/JameZUK/lyrion-anywhere/releases/latest/download/repo.xml
```

## The quality badge says what you hear

Playing a 24/96 FLAC on mobile data, the badge by the track said **FLAC 24/96 · Hi-Res** while the panel it opened said *Lossy source, Opus 48 kHz*. Both described something true (the library file, and the re-encoded stream), neither answered the question. Redesigned, the same in the web app and on Android:

- **The badge states the weakest link, then what is heard:** *Hi-Res · FLAC 24/96*, *Lossless · FLAC 16/44.1*, *Transcoded · Opus 160*, *Lossy · MP3 320*. Only codecs and re-encoding decide the word; your device's resampling, EQ, ReplayGain and volume never do. Transcoded and Lossy carry a subtle amber tint.
- **The panel is a block diagram:** *File* → *LMS* (only when LMS converted the codec, lowered the rate or depth, or applied ReplayGain) → *Lyrion gateway* (passed through unchanged, or re-encoded to Opus and why) → *This device* (what arrived, the output and its rate). The block that lowered the quality is tinted. Everything the old panel showed is under *Details*. A remote player shows *File → Player*; a download played offline shows *Download → This device*.
- **Change the streaming quality from the panel:** *Original · High · Data saver* under the gateway block override your setting for this session (until the app restarts or the network type changes) and take effect at once, by restarting the stream where it is. The gateway confirms the level before the restart, so the two cannot cross.
- Both apps draw from one shared model with the same test vectors, so they cannot drift apart.

## Volume

- **A new player starts at full volume.** LMS gives a player it has never seen a volume of 50, so the first play on a fresh browser or phone was quiet. The gateway now sets a device's player to 100 the first time it attaches, once per device; existing devices keep whatever their owners chose.
- **Fix this player's output level at 100%**, on by default in each app (web: *Settings › About › Advanced*; Android: *Settings › Sound*): the device sets its own player's *Volume Control* in Lyrion to "Output level is fixed at 100%", so the device's volume is the only one that matters and no controller can turn it down. Untick it to give LMS the volume back. Any player whose output level is fixed shows "Output level is fixed at 100%" instead of a slider.

## The settings page

- **Allow http://** was a one-off confirmation that looked like a setting, and a refused `http://` address vanished from the field together with the box it asked you to tick. Now a refused address stays in the field, the tick is needed only when an `http://` address is set or changed (the saved one is accepted again without it), and saving one is confirmed with a notice that connections to it are unencrypted.
- The *Devices* list tags a device whose app is too old for this plugin with *needs updating*.

## Protocol 2, for the curious

The gateway tells the player, for every stream, what LMS served (codec; rate, depth and channels read from a FLAC stream's header; server ReplayGain) and what the gateway sent (passed through, or Opus at which level), and the player states its protocol version when it signs in. An app below version 2 is closed with a dedicated code and a plain "update the app"; a server below version 2 is named by the app as needing plugin 0.7.3. Details in [`docs/PROTOCOL.md`](https://github.com/JameZUK/lyrion-anywhere/blob/main/docs/PROTOCOL.md) under *Versions*. This is the project's standing rule from now on: doing it properly overrules backwards compatibility, and the release notes say what to update.
