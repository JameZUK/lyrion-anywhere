Lyrion Anywhere **0.8.1** fixes signing in to the web app with two-step verification. The player protocol stays at 2, so **Lyrion Anywhere for Android 1.17.0** or later keeps working; the Android app is not affected and has no new release.

**Install or update:** add this repository in *Settings › Plugins › Additional repositories* (if you haven't already), then install or update **Lyrion Anywhere**:

```
https://github.com/JameZUK/lyrion-anywhere/releases/latest/download/repo.xml
```

## Signing in with an authenticator code

- **The web app refused every code** with the browser's "Match the requested format" before anything was sent, so an account with two-step verification could not sign in on the web. The field's format rule was written wrongly and had been since the first web release. It is fixed, and the code fields in *Settings › Account* take a code with or without its middle space.
- **"Too many attempts" after trying:** each try with the right password and no accepted code counts towards the sign-in limit (five in 15 minutes), so you may have locked your address out while trying. The lock ends by itself after 15 minutes (longer if it was hit repeatedly); *Restart gateway* on the plugin's settings page clears it at once.
- **Tested in a browser from now on.** Turning two-step verification on, signing in with a code, changing the password and turning it off are now driven in a real browser on every change.

## If your reverse proxy adds HSTS

The 0.8.0 notes said a proxy's own `Strict-Transport-Security` header beside the gateway's does no harm. That was wrong: browsers use only the first of two, which is the gateway's (one year, this host only). Remove the proxy's, or to keep a policy of your own have the proxy hide the gateway's (nginx: `proxy_hide_header Strict-Transport-Security;`).

The full list is in the [changelog](https://github.com/JameZUK/lyrion-anywhere/blob/main/CHANGELOG.md).
