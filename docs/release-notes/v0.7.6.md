Lyrion Anywhere **0.7.6** fixes an update problem on the plugin's settings page. The player protocol stays at 2, so **Lyrion Anywhere for Android 1.17.0** or later keeps working, and there is no Android release this time.

**Install or update:** add this repository in *Settings › Plugins › Additional repositories* (if you haven't already), then install or update **Lyrion Anywhere**:

```
https://github.com/JameZUK/lyrion-anywhere/releases/latest/download/repo.xml
```

## The settings page after an update

- **The settings page could keep the previous release's script after an update from the zip.** The page's script URL carries a stamp so browsers fetch it again when it changes, but the stamp was taken from the files' dates, every file in the release zip was dated 1 January 2020, and LMS lets browsers keep plugin files for a week. So after an update, a browser that had opened the page before went on running the old script for up to a week. That is why the transcoding line added in 0.7.5 did not appear for the reporter of [#29](https://github.com/JameZUK/lyrion-anywhere/issues/29). The stamp is now a hash of the files' contents.
- **Release zips are dated with the commit they were built from.** LMS also keeps a compiled copy of a plugin's page template and goes on using it while the template's date is unchanged, so a constant date could have kept the previous release's page as well. Each release now carries its own date.
- **Nothing to do after updating:** the 0.7.6 page refers to its script by the new stamp, so browsers fetch it. If you stay on 0.7.5 and the Status panel shows no "Transcoding with …" line, a forced reload of the settings page (Ctrl+F5, or Shift+reload on a Mac) gets the current script.

The full list is in the [changelog](https://github.com/JameZUK/lyrion-anywhere/blob/main/CHANGELOG.md).
