Lyrion Anywhere **0.7.1** fixes the white screen some people saw in the **installed (home-screen) web app** after updating to 0.7.0, and makes the web app update itself from now on. The gateway and the plugin are otherwise as in [0.7.0](https://github.com/JameZUK/lyrion-anywhere/releases/tag/v0.7.0); Android [1.16.0](https://github.com/JameZUK/lyrion-anywhere/releases/tag/android-v1.16.0) is unchanged. Update from *Settings › Plugins* in LMS; LMS restarts to load it.

**Install or update:** add this repository in *Settings › Plugins › Additional repositories* (if you haven't already), then install or update **Lyrion Anywhere**:

```
https://github.com/JameZUK/lyrion-anywhere/releases/latest/download/repo.xml
```

## The white screen, and the fix

On devices where the browser's storage for the installed app misbehaves (seen on an iPad), the app's service worker could keep serving an out-of-date copy of the page whose start-up script the server no longer had, and quitting the app did not help: the new version never installed because storing its files failed in the same way. The worker fetched the page and wrote it to its cache in one step, and a failed write was treated like being offline.

- **The page from the server always wins.** The stored copy is used only when the network itself fails. Writing to the cache is best-effort and can never change what you are served; installing a new version completes even if nothing can be stored; only one previous version is kept.
- **Updates apply themselves.** A new version installs and takes over straight away, unless music is playing on this device: then the quiet *A new version is ready* offer shows as before, and the update applies the moment playback here stops. *Later* holds it until the next version or the next launch. The app looks for a new version on every launch and once an hour while open.
- **A boot guard.** If the app has not started ten seconds after loading while you are online, a small script clears the app's stored copy and service worker and reloads once, at most once every five minutes, so a broken stored copy repairs itself.
- **The worker stores everything the page references**, including the start-up script, which it used to leave out.

**If your installed app is already stuck on the white screen:** open it once after your server has 0.7.1 (it will still be white), quit it fully, and open it again; the new worker installs in the background during that first open and takes over on the next. If it is still white after that, remove the app from your home screen and add it again once.

## Tests

Regression tests drive the worker with a cache that refuses writes, opens or deletes (the page from the server is served, the install completes, pruning never fails); unit tests cover the update decision table and the boot guard; and an opt-in browser check (`web/app/tests/e2e/pwa-update.mjs`) relaunches the installed app in a persistent Chromium profile across an update, a broken stored shell and a failing cache, reproducing the 0.7.0 white screen and showing it gone.
