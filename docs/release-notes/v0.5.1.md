Lyrion Anywhere **0.5.1** makes the web app say what is actually streaming. It changes the web app only; the gateway and the plugin's behaviour are as in 0.5.0, and Android [1.15.3](https://github.com/JameZUK/lyrion-anywhere/releases/tag/android-v1.15.3) remains current. Update from *Settings › Plugins* in LMS; LMS restarts to load it.

**Install or update:** add this repository in *Settings › Plugins › Additional repositories* (if you haven't already), then install or update **Lyrion Anywhere**:

```
https://github.com/JameZUK/lyrion-anywhere/releases/latest/download/repo.xml
```

## What changed

People who set *High* on an iPhone saw the signal path describe a 96 kHz FLAC as 48 kHz "in MP4" and asked whether it was a display error. The conversion was real and intended: for *High* and *Data saver* the gateway re-encodes FLAC to Opus on the fly, and Opus is always 48 kHz; Safari then plays the decoded audio through its media player, wrapped losslessly as FLAC in MP4. What was wrong was the panel: it never said "Opus", and its verdict came from the library track, so it could read "Lossless to the browser" while a lossy stream played. There was no way to tell from the app whether Opus was in use at all. This release fixes that in every browser; the information comes from the player engine, not from the browser.

**Web app**
- **The quality badge on Now playing shows the stream, not just the track:** "Opus 160" (or "Opus 96") whenever the gateway re-encoded it, and the track's own badge ("FLAC 24/96 · Hi-Res") when it is streamed as stored. Other players' badges are unchanged, since only this device knows its own stream.
- **The signal path has a *Stream to this device* row:** "Opus 160 kb/s, re-encoded by the gateway for the High setting", "FLAC 24-bit, as stored (not re-encoded)", or "Not known yet" before the first audio is decoded. The first row is now *Track in the library*. The media-element output is described as "the decoded audio, re-wrapped losslessly as FLAC in MP4", the rate row adds "(Opus is always 48 kHz)", and the verdict reads "Re-encoded to Opus 160 kb/s", never "lossless", with a note on getting the original back in *Settings › Playback*.
- ***Automatic* streaming quality explains itself per browser.** Chrome on Android reports its connection, so *Automatic* can pick *High* on mobile data there. Firefox and Safari (every iPhone and iPad) have no such API, so there *Automatic* always means *Original*, and the setting now says so: "Always Original in this browser, which can't tell mobile data from Wi-Fi. Choose High or Data saver yourself when you're on mobile data." The *High* and *Data saver* notes give the data rate per hour.

**Under the hood**
- The player engine's status carries the decoded stream's codec, whether it is lossless, its bit depth and channels (the Android app already used this). The web app checks the value before showing it.
- Tests cover the engine's status before, during and after a track; every kind of stream in the signal path, with and without track details from LMS, on both output paths; the badge; the per-browser note; and hostile values.
